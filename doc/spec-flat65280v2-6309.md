# flat65280v2 Machine Specification (gep9)

This document defines the hardware environment, memory architecture, memory-mapped I/O devices, and operating conventions for the **flat65280v2** engine implemented in the `gep9` 6809/6309 virtual machine.

The `flat65280v2` engine is designed to run **NitrOS-9 Level 1** (as well as standalone 6809/6309 kernels, bootloaders, and firmware) within a flat, unsegmented 64KB address space without hardware task memory isolation or MMU paging.

---

## 1. Engine Selection & Overview

The `gep9` emulator supports multiple execution profiles selected via the `--engine` command-line flag:

| Engine | Flag | Description |
|:---|:---|:---|
| **Hatvan** | `--engine=hatvan` *(default)* | 256 isolated 64KB task spaces, TaskFuse (`$FF20`), DMA copy engine (`$FF21..$FF27`), Hatvan disk controller (`$FF10..$FF17`), Turbo9Sim timer (`$FF02..$FF03`), and memory curtaining. |
| **flat65280v2** | `--engine=flat65280v2` | Single flat 64KB address space, no tasks or memory banking, 65,280 bytes of contiguous RAM (`$0000..$FEFF`), and a protected 256-byte I/O page (`$FF00..$FFFF`) hosting EMUDSK and ACIA serial devices. |

To invoke `gep9` with the `flat65280v2` engine:

```bash
./build/gep9 --engine=flat65280v2 [options] <program.decb|system.img> [listing.list ...]
```

---

## 2. CPU Architecture

The simulated processor is a clean-room implementation of the **Hitachi 6309** CPU (fully backward-compatible with the Motorola 6809):

* **Standard 6809 Registers:** Accumulators `A` and `B` (concatenated 16-bit register `D`), Index registers `X` and `Y`, Stack pointers `S` (Hardware Stack) and `U` (User Stack), Program Counter `PC`, Direct Page register `DP`, and Condition Code register `CC`.
* **Hitachi 6309 Extensions:** Native Mode accumulator `E` and `F` (concatenated 16-bit register `W`), 32-bit register `Q` (`D:W`), 16-bit register `V`, Mode Register `MD`, block transfers (`TFM`), and 32-bit arithmetic instructions.
* **CPU Clock & Timing:** Simulated CPU frequency defaults to 2 MHz (`--cpu-hz=2000000`), used to calculate real-time cycle intervals and execution timeouts.
* **Reset State:**
  * CPU boots in 6809 Emulation Mode (`MD = $00`).
  * Interrupt masks set: `CC` has `FlagI` (`$10`) and `FlagF` (`$40`) asserted.
  * Direct Page register initialized to `$00`.
  * Initial `PC` is fetched from the 16-bit Reset Vector at `$FFFE..$FFFF`.

---

## 3. Memory Map

The 16-bit physical address space ($0000..$FFFF, 65,536 bytes) is organized as follows:

| Address Range (Inclusive) | Size | Classification | Function / Device |
|:---|:---|:---|:---|
| `$0000..$FEFF` | 65,280 bytes (`$FF00`) | **Flat RAM** | Read/Write RAM for OS kernel, drivers, system buffers, user code, and stacks. |
| `$FF00..$FF7F` | 128 bytes | **Unmapped** | Red Page guard band (Stray read/write fault). |
| `$FF80..$FF86` | 7 bytes | **I/O Device** | **EMUDSK** Virtual Block Storage Controller. |
| `$FF87` | 1 byte | **I/O Device** | **CLOCK_AND_STOP** Periodic Interrupting Clock & Emulator Control. |
| `$FF88..$FF89` | 2 bytes | **I/O Device** | **ACIA_M6805** (MC6850 UART) Console Serial Interface. |
| `$FF8A..$FFEF` | 102 bytes | **Unmapped** | Red Page guard band (Stray read/write fault). |
| `$FFF0..$FFFF` | 16 bytes | **System Vectors** | Read-only CPU Exception & Reset Vector Table. |

> [!NOTE]
> Address ranges use `..` to indicate **inclusive** bounds (for example, `$FF80..$FF86` includes both `$FF80` and `$FF86`).

## 4. Hardware I/O Devices

In `flat65280v2`, three memory-mapped peripheral devices exist in the top page:

### 4.1 EMUDSK Block Storage Controller (`$FF80..$FF86`)

EMUDSK implements the standard NitrOS-9 virtual block storage interface. It provides fast, synchronous DMA transfers between attached raw disk images and system RAM.

#### Register Layout

| Address | Name | Access | Description |
|:---|:---|:---|:---|
| `$FF80` | `LSN[23:16]` | R/W | High byte of 24-bit Logical Sector Number |
| `$FF81` | `LSN[15:8]` | R/W | Middle byte of 24-bit Logical Sector Number |
| `$FF82` | `LSN[7:0]` | R/W | Low byte of 24-bit Logical Sector Number |
| `$FF83` | `COMMAND` / `STATUS` | R/W | **Write**: Initiates operation (`0`=Read, `1`=Write, `2`=Close).<br>**Read**: Returns status result code (`0`=Success). |
| `$FF84` | `BUFFER[15:8]` | R/W | High byte of 16-bit big-endian RAM buffer target address |
| `$FF85` | `BUFFER[7:0]` | R/W | Low byte of 16-bit big-endian RAM buffer target address |
| `$FF86` | `DRIVE` | R/W | Drive unit selection (`0` = Drive 0 / `--disk0`, `1` = Drive 1 / `--disk1`) |

#### Operational Characteristics

* **Sector Size:** Sectors are fixed at **256 bytes**.
* **Synchronous Execution:** Writing the command byte to `$FF83` triggers an immediate synchronous sector transfer; no busy-polling loops are required. The result status is immediately available for reading at `$FF83`.
* **Buffer Bounds:** The target buffer address in `$FF84..$FF85` points into flat RAM (`$0000..$FEFF`). If a sector transfer spills into the protected I/O page (`buffer + 256 > $FF00`), the controller aborts and returns an error code.
* **Multi-Drive Mapping:**
  * Drive unit `0` maps to the disk image passed via `--disk0=<path>`.
  * Drive unit `1` maps to the disk image passed via `--disk1=<path>`.
* **Status Return Codes (`$FF83` Read):**
  * `0`: Success / OKAY.
  * `2`: Drive not ready or not attached (`E$NotRdy`).
  * `6`: Sector offset out of disk bounds or buffer address invalid (`E$CRC` / seek error).
  * `254`: Invalid / unsupported command byte.

#### 6809 Assembly Example (EMUDSK Read/Write)

```asm
EMU_LSN     equ   $FF80
EMU_CMD     equ   $FF83
EMU_BUF     equ   $FF84
EMU_DRV     equ   $FF86

* Read Sector 0 of Drive 0 into $2000
ReadSect0:
            clr   EMU_DRV             ; Select Drive 0
            clr   EMU_LSN             ; LSN[23:16] = 0
            clr   EMU_LSN+1           ; LSN[15:8]  = 0
            clr   EMU_LSN+2           ; LSN[7:0]   = 0
            ldx   #$2000
            stx   EMU_BUF             ; Target RAM address = $2000
            clr   EMU_CMD             ; Command 0 = Read Sector
            lda   EMU_CMD             ; Read status code
            bne   DiskError           ; Non-zero indicates error
            rts

* Write Sector 1 of Drive 0 from $2000
WriteSect1:
            clr   EMU_DRV             ; Select Drive 0
            clr   EMU_LSN             ; LSN[23:16] = 0
            clr   EMU_LSN+1           ; LSN[15:8]  = 0
            lda   #1
            sta   EMU_LSN+2           ; LSN[7:0]   = 1
            ldx   #$2000
            stx   EMU_BUF             ; Source RAM address = $2000
            lda   #1
            sta   EMU_CMD             ; Command 1 = Write Sector
            lda   EMU_CMD             ; Read status code
            bne   DiskError
            rts

DiskError:  coma                      ; Set carry flag to indicate OS-9 error
            rts
```

### 4.2 CLOCK_AND_STOP Periodic Clock & Emulator Control (`$FF87`)

The `CLOCK_AND_STOP` port at `$FF87` provides a programmable periodic interrupting system clock and immediate emulator lifecycle controls (exit and crash/core dump triggers).

#### Register Layout (`$FF87`)

| Bit(s) | Name | Access | Function / Description |
|:---|:---|:---|:---|
| **0** | `TICK` / `FIRE` | R / W1C | **Firing Condition / Clock Tick Flag**:<br>• **Read**: `1` = Clock has ticked / interrupt pending; `0` = Cleared / idle.<br>• **Write**: Writing a byte with bit 0 set to `1` resets this flag to `0`. Writing a byte with bit 0 as `0` leaves this flag unaltered. |
| **1** | `IRQ_EN` | R/W | **IRQ Enable**: `1` = Asserts the CPU `IRQ` line whenever bit 0 (`TICK`) is `1`; `0` = Masks/disables hardware IRQ generation from the clock. |
| **2..3** | `USER[1:0]` | R/W | General-purpose read/write bits; preserved as written by the user. |
| **4..5** | `RATE[1:0]` | R/W | **Clock Frequency Select** (Bits `$30`):<br>• `$00` (`00`): **60 Hz** (default, ~33,333 cycles at 2 MHz)<br>• `$10` (`01`): **50 Hz** (~40,000 cycles at 2 MHz)<br>• `$20` (`10`): **6 Hz** (~333,333 cycles at 2 MHz)<br>• `$30` (`11`): **0.1 Hz** (1 tick every 10 seconds, ~20,000,000 cycles at 2 MHz) |
| **6..7** | `USER[3:2]` | R/W | General-purpose read/write bits; preserved as written by the user. |

#### Operational Characteristics & Rules

1. **Hardware Tick Event**:
   - Each time the configured interval elapses, hardware sets bit 0 (`TICK |= 0x01`).
   - If bit 1 (`IRQ_EN`) is `1`, the CPU's `IRQ` interrupt line is immediately asserted.
2. **Interrupt Acknowledgment (Write-1-to-Clear / W1C)**:
   - To acknowledge a tick, software writes to `$FF87` with bit 0 set to `1` (for example, `LDA #$03; STA $FF87` or `LDA #$01; STA $FF87`).
   - If software writes a byte where bit 0 is `0` (for example, `LDA #$02; STA $FF87`), the firing condition (bit 0) is **not altered** and remains `1`.
   - The user cannot turn on bit 0 by writing to the register. Only the periodic clock can turn on bit 0.
3. **User Read/Write Bits**:
   - All bits besides the low bit (bits 7..1) are standard read/write bits, only set by the user. When reading `$FF87`, bits 7..1 return the exact values written by the CPU.
4. **Special Control Codes (Abrupt Halt & Crash)**:
   - Writing specific high-range byte values to `$FF87` causes the emulator to stop abruptly. Before halting, the emulator prints an explanatory message to both standard output (`stdout`) and standard error (`stderr`) and flushes both streams:
     - **`$FC`**: Prints `\n *** Exiting with status 0 due to CLOCK_AND_STOP command $FC.\n` and exits with host exit code 0 (`exit(0);`).
     - **`$FD`**: Prints `\n *** Exiting with status 1 due to CLOCK_AND_STOP command $FD.\n` and exits with host exit code 1 (`exit(1);`).
     - **`$FE`**: Prints `\n *** Crashing due to CLOCK_AND_STOP command $FE.\n` and induces an immediate host crash and core dump (via `SIGABRT` / `panic`).

#### 6809 Assembly Example (Clock Initialization & ISR)

```asm
CLOCK_PORT  equ   $FF87

* Initialize Clock: 60 Hz rate, IRQ enabled
InitClock:
            lda   #$02                ; Rate = 60Hz ($00), IRQ Enable = 1 ($02), low bit = 0
            sta   CLOCK_PORT
            andcc #^$10               ; Clear FlagI (enable CPU IRQs)
            rts

* Clock Interrupt Service Routine (IRQ)
ClockISR:
            lda   CLOCK_PORT          ; Read clock status
            bita  #$01                ; Did the clock tick?
            beq   NotClock            ; If not, check other devices (e.g. ACIA)
            lda   #$03                ; Keep IRQ enabled ($02), reset tick flag ($01)
            sta   CLOCK_PORT          ; Acknowledge clock tick (W1C on bit 0)
            inc   TickCounter         ; Update OS tick count
            rti                       ; Resume interrupted code

NotClock:   jmp   CheckACIA           ; Dispatch next handler in interrupt chain

* Program Exit via CLOCK_AND_STOP
ExitProgram:
            lda   #$FC                ; Special halt code for exit(0)
            sta   CLOCK_PORT          ; Abruptly halts gep9 emulator
```

### 4.3 ACIA_M6805 Serial Interface (`$FF88..$FF89`)

Console terminal communication uses a Motorola MC6850-compatible Asynchronous Communications Interface Adapter (ACIA) mapped at `$FF88..$FF89`.

#### Register Layout

| Address | Name | Access | Description |
|:---|:---|:---|:---|
| `$FF88` | `STATUS` | Read-Only | ACIA Status Register (Rx Ready, Tx Empty, IRQ flags). |
| `$FF88` | `CONTROL` | Write-Only | ACIA Control Register (Master Reset, Baud/Divider, Word format, Interrupt Enable). |
| `$FF89` | `DATA` (Rx) | Read-Only | Receive Data Register (returns next received byte). |
| `$FF89` | `DATA` (Tx) | Write-Only | Transmit Data Register (transmits byte to console output). |

#### ACIA Status Register (`$FF88` Read)

| Bit | Name | State in Emulator | Description |
|:---|:---|:---|:---|
| **0** | `RDRF` | Dynamic | **Receive Data Register Full**: `1` = Received character ready in Data register; `0` = Empty. |
| **1** | `TDRE` | Fixed `1` | **Transmit Data Register Empty**: Always `1` (terminal can always accept output). |
| **2** | `DCD` | Fixed `0` | Data Carrier Detect (always active/carrier present). |
| **3** | `CTS` | Fixed `0` | Clear to Send (always active). |
| **4** | `FE` | Fixed `0` | Framing Error (none). |
| **5** | `OVRN` | Fixed `0` | Receiver Overrun (none). |
| **6** | `PE` | Fixed `0` | Parity Error (none). |
| **7** | `IRQ` | Dynamic | **Interrupt Request**: Set to `1` when `RDRF == 1` **and** Receive Interrupts are enabled in Control register (`RIE == 1`). |

#### ACIA Control Register (`$FF88` Write)

| Bits | Function | Behavior |
|:---|:---|:---|
| **0..1** | Counter Divide / Reset | `00` = /1, `01` = /16, `10` = /64, `11` = **Master Reset**. Writing `$03` clears internal control registers, disables interrupts, and deasserts the IRQ line. |
| **2..4** | Word Select | Selects word length, parity, and stop bits (modeled transparently). |
| **5..6** | Transmitter Control | Controls RTS and Tx interrupt enable. |
| **7** | `RIE` (Rx Interrupt Enable) | `1` = Enable Receive Interrupt; `0` = Disable Receive Interrupt. When set, asserting `RDRF` immediately asserts the CPU's **IRQ** line. |

#### Data Register Operations (`$FF89`)

* **Reading `$FF89` (Rx Data):**
  * Retrieves and consumes the oldest pending character from the console input queue.
  * If the input queue becomes empty, bit 0 (`RDRF`) of Status is cleared to `0`, and the CPU's IRQ line is deasserted.
  * If read when empty, returns `$00`.
* **Writing `$FF89` (Tx Data):**
  * Transmits the byte to standard output (`os.Stdout`).
  * Carriage return (`$0D` / `\r`) or line feed (`$0A` / `\n`) is formatted as a newline.
  * Non-printable control characters are escaped as `{%d}` unless `--curly-escape=false` is set.

#### 6809 Assembly Example (Polled Console I/O)

```asm
ACIA_STAT   equ   $FF88
ACIA_CTRL   equ   $FF88
ACIA_DATA   equ   $FF89

* Initialize ACIA (Master Reset, then 8-N-1 with Interrupts Disabled)
InitAcia:
            lda   #$03                ; Master Reset
            sta   ACIA_CTRL
            lda   #$11                ; /16 divider, 8-bit no parity 1 stop, IRQ disabled
            sta   ACIA_CTRL
            rts

* Send a single character in Register A to Console
PutChar:
            pshs  a
.waitTx:    lda   ACIA_STAT
            bita  #$02                ; Check TDRE (bit 1)
            beq   .waitTx
            puls  a
            sta   ACIA_DATA           ; Send character
            rts

* Read a single character into Register A (blocking loop)
GetChar:
            lda   ACIA_STAT
            bita  #$01                ; Check RDRF (bit 0)
            beq   GetChar             ; Wait until character ready
            lda   ACIA_DATA           ; Read character
            rts
```

## 5. System Exception & Reset Vectors (`$FFF0..$FFFF`)

The top 16 bytes contain standard 6809/6309 CPU exception and reset vectors (all addresses are 16-bit big-endian words):

| Address Range | Vector | Trigger | Description |
|:---|:---|:---|:---|
| `$FFF0..$FFF1` | `TRAP` | 6309 Trap | Native 6309 illegal opcode or division by zero |
| `$FFF2..$FFF3` | `SWI3` | `SWI3` instruction | User software interrupt 3 |
| `$FFF4..$FFF5` | `SWI2` | `SWI2` instruction | **NitrOS-9 System Call Entry Point** (`OS9 <call>`) |
| `$FFF6..$FFF7` | `FIRQ` | Fast Interrupt | Fast interrupt request |
| `$FFF8..$FFF9` | `IRQ` | Interrupt | **ACIA Console Rx & CLOCK_AND_STOP Timer Interrupt** |
| `$FFFA..$FFFB` | `SWI` | `SWI` instruction | Software interrupt / breakpoint monitor |
| `$FFFC..$FFFD` | `NMI` | Non-Maskable | Non-maskable interrupt |
| `$FFFE..$FFFF` | `RESET` | Power-on / Reset | **CPU Initial Program Counter (`PC`)** |

* **Vector Initialization:** Vectors are loaded from binary files during emulator initialization (either via raw 64KB `.img`/`.rom` images or DECB execution chunk headers).
* **Runtime Vector Reads:** CPU vector fetches (and read instructions such as `LDX $FFFE`) read directly from memory without faulting.

## 6. Hardware Fault & Protection Rules

To catch stray pointers, stack overflows, and incorrect hardware probes:

1. **Stray Reads (`$FF00..$FFEF`):**
   * Any read outside the valid peripheral register range (`$FF80..$FF89`) will trigger a **Stray Read Fault** (`ErrFlatStrayRead`) and cause the emulator to halt immediately:
     ```
     panic: flat65280v2: stray read in $FF00..$FFEE: read at 0xFF00
     ```
2. **Stray Writes (`$FF00..$FFFF`):**
   * Any write in the top page outside designated write registers (`$FF80..$FF89`) will trigger a **Stray Write Fault** (`ErrFlatStrayWrite`) and cause the emulator to halt immediately:
     ```
     panic: flat65280v2: stray write in $FF00..$FFFF: write at 0xFFFE
     ```
   * **Vector Table Write Protection:** System Vectors at `$FFF0..$FFFF` are strictly write-protected during program execution. Attempting to overwrite a vector at runtime will trigger a Stray Write Fault.

## 7. Supported Binary Formats

The `flat65280v2` engine accepts two binary formats:

### 7.1 Raw 64KB System Images (`.img`, `.rom`)

Files with extension `.img`, `.rom`, or exactly 65,536 bytes in size are loaded directly:
* All 65,536 bytes are copied directly into `$0000..$FFFF`.
* Vectors at `$FFF0..$FFFF` are populated directly from the top 16 bytes of the image file.
* The CPU resets and begins execution at the address pointed to by `$FFFE..$FFFF`.

### 7.2 Extended DECB Binaries (`.decb`)

Radio Shack Color Computer DECB binaries with extended symbolic headers:
* `$00` (`DECB_DATA`): Loads raw binary data segments directly into memory.
* `$FF` (`DECB_EXEC`): Specifies execution start address. Automatically sets the Reset Vector at `$FFFE..$FFFF` and sets initial `PC`.
* Extended chunks (`$01` absolute source line, `$02` module declaration, `$03` module source, `$04` absolute symbol, `$05` module symbol) are scanned for annotated execution traces.

### 7.3 Automatic OS-9 Module Scanning & Listings

When loading a raw image or DECB file, `gep9` scans `$0000..$FF00` for valid OS-9 module headers (`$87 $CD`). Any assembly listing files (`.list` or `.lst`) passed on the command line matching module names are automatically offset-adjusted to match module in-memory load addresses for source tracing.

## 8. Command-Line Reference

```
Usage: gep9 --engine=flat65280v2 [options] <binary.decb|system.img> [listing.list ...]
```

### Options

| Flag | Default | Description |
|:---|:---|:---|
| `--engine <name>` | `"hatvan"` | Set to `"flat65280v2"` for flat 64K unsegmented NitrOS-9 Level 1 execution. |
| `--disk0 <path>` | `""` | Disk image file for Drive 0 (accessed via EMUDSK `$FF86 = 0`). |
| `--disk1 <path>` | `""` | Disk image file for Drive 1 (accessed via EMUDSK `$FF86 = 1`). |
| `--input <str>` | `""` | Initial console string fed into ACIA serial receiver (translates `\n` to OS-9 `\r`). |
| `--trace` | `false` | Enables CPU instruction execution trace (registers, CC, disassembled line). |
| `--max-cycles <N>` | `0` | Halts simulation after $N$ CPU cycles (0 = unlimited). Useful for automated test scripts. |
| `--max-seconds <N>` | `300` | Halts simulation after $N$ real-time seconds (0 = unlimited). |
| `--cpu-hz <N>` | `2000000` | Simulated CPU clock frequency in Hz (default 2 MHz). |
| `--curly-escape` | `true` | Escapes unprintable console characters as `{%d}`. Set to `false` for raw terminal output. |
| `--hypercalls` | `false` | Enables GOMAR hypercall traps (`fcb $12,$21,<hop>`). Hop 107 halts emulator with exit code in register `D`. |
| `--print-cycles` | `false` | Prints total executed CPU cycles upon exit. |

## 9. Comparison: Hatvan Engine vs. flat65280v2 Engine

| Feature | `--engine=hatvan` | `--engine=flat65280v2` |
|:---|:---|:---|
| **Target OS** | Hatvan OS (Multi-tasking microkernel) | NitrOS-9 Level 1 / Standalone 6809 Kernels |
| **Memory Model** | 256 independent 64KB task spaces | Single flat 64KB space (`$0000..$FEFF` RAM) |
| **MMU & Task Switching** | Hardware TaskFuse (`$FF20`), DMA copy | None (flat linear addressing) |
| **Disk Interface** | Hatvan Disk Controller (`$FF10..$FF17`) | EMUDSK Virtual Controller (`$FF80..$FF86`) |
| **Console Interface** | Turbo9Sim Polled Character I/O (`$FF00..$FF01`) | MC6850 ACIA UART (`$FF88..$FF89`) |
| **Hardware Timer** | Turbo9Sim 60Hz Timer IRQ (`$FF02..$FF03`) | CLOCK_AND_STOP Periodic Timer (`$FF87`: 60Hz, 50Hz, 6Hz, 0.1Hz, and abrupt stops `$FC`, `$FD`, `$FE`) |
| **Console Interrupt** | Turbo9Sim Control register (`$FF03` bit 1) | ACIA Control register (`$FF88` bit 7 `RIE`) |
| **Top Page Protection** | Task 0 kernel panic; Tasks 1..255 core dump | Stray Read Fault (`$FF00..$FFEF`), Stray Write Fault (`$FF00..$FFFF`) |
| **Companion Drivers** | Autoloads `rbf_6809.decb` and `procfs_6809.decb` | Disabled (no driver tasks loaded) |
